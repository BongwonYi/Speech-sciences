1.3질문을 좁히기 ★ · narrowing the question

가장 흔한 실패

수업 프로젝트가 실패하는 이유는 대개 기술이 부족해서가 아니라 질문이 너무 크기 때문이다.

“한국어 파열음을 분석한다”는 주제일 뿐 질문이 아니다. “20대 서울 화자에서 평음과 격음의 VOT가 겹치는가”처럼 써야 질문이 된다.

비교 대상이 있는가“마찰음을 본다”“/ㅅ/과 /ㅆ/의 COG를 비교한다”

1.4이 규모로 무엇을 할 수 있나 ★ · what this sample size can detect

질문을 좁혔다면 다음에 물을 것은 우리가 모을 수 있는 자료로 그 질문에 답할 수 있느냐다. 수업 프로젝트의 규모는 대개 집단당 8~20명이므로, 그 정도 인원으로 어떤 크기의 차이를 잡을 수 있는지 미리 알고 시작하는 편이 좋다.

집단당 16명이면 효과크기(effect size) d가 1.03은 되어야 80 % 확률로 유의한 결과가 나온다. 그런데 d = 1.0은 매우 큰 차이다. 10주차에서 본 노년·청년 세대의 VOT 병합 정도가 바로 그 수준(d 4.25 → 1.02)이었다.

뒤집어 말하면, 중간 크기 효과(d = 0.5)는 16명으로 28 %밖에 잡지 못한다. 실제로 차이가 있어도 열 번 가운데 일곱 번은 놓친다는 뜻이다. 연구 트랙 A1에서 참 효과크기를 아는 자료로 이 현상을 직접 확인한다.

그래서 프로젝트를 이렇게 설계한다

첫째, 큰 효과가 기대되는 질문을 고른다. 남녀 포먼트 차이나 평음–격음 VOT 차이처럼 이미 크다고 알려진 것이 안전하다. 미묘한 차이를 찾으려는 야심 찬 질문일수록 “차이 없음”으로 끝나기 쉽다.

둘째, 화자 간 비교보다 화자 내 비교(within-speaker design)를 쓴다. 같은 사람이 두 조건을 모두 수행하면(예: 낭독과 자유발화) 개인차가 상쇄되어 훨씬 적은 인원으로도 차이가 검출된다. 이 수업 규모에서는 거의 언제나 이쪽이 낫다.

셋째, “유의하지 않았다”를 실패로 여기지 않는다. 위 표를 근거로 “이 표본으로는 d가 1보다 작은 차이를 잡을 수 없었다”고 쓰면 그것이 정확한 보고다. 제한점 절에 이 표를 인용한다.

§2두 단계로 진행하기　two-stage project design

두 트랙 공통 · 계획은 0:30–0:45에, 작업은 0:45부터

학기 내내 실습을 합성음(A)과 실제 녹음(B) 두 단계로 해 왔다. 프로젝트도 같은 순서를 따른다. 이번에는 절차를 교수자가 정해 주지 않으므로, 각 조가 자기 질문에 맞는 A 자료와 B 자료를 직접 고르고, 둘 사이에서 무엇이 달라지는지를 결과의 일부로 보고한다.

2.1단계 A — 정답을 아는 자료로 파이프라인 검증 · stage A · known-answer validation

분석 파이프라인(analysis pipeline)은 녹음 파일을 넣으면 표와 그림이 나오는 일련의 절차다. 이 절차가 맞는지 확인하는 가장 확실한 방법은 답을 아는 자료를 넣어 보는 것이다. 합성 자료(synthetic data)는 입력값을 우리가 정했으므로, 되분석(re-analysis)한 값이 입력값과 얼마나 가까운지 바로 잴 수 있다.

검증할 것통과 기준 예시
값이 회수되는가포먼트·VOT처럼 입력값이 분명한 지표는 ±5 % 안 (8주차 허용 오차와 같은 근거)
순서와 방향이 맞는가jitter처럼 입력과 측정의 정의가 다른 지표는 절대값보다 프로파일 사이의 순서가 맞는지 본다
건드리지 않은 지표가 가만히 있는가모음 공간만 줄인 프로파일에서 음원 지표가 정상과 같게 나와야 한다. 움직이면 그 지표는 특이도(specificity)가 낮다
통계 코드가 맞는가손으로 계산할 수 있는 작은 예와 참 효과크기를 아는 자료에서 같은 값이 나와야 한다

A 자료는 두 가지다. 이번 주에 새로 준비한 묶음(아래 A 자료 내려받기)에는 임상 트랙의 합성 프로파일과 연구 트랙의 두 집단 비교 자료가 들어 있다. 그 밖의 측정(포먼트, VOT, COG, 말속도, 범주 지각)은 9~13주차 실습 A 자료를 그대로 다시 쓰면 된다. 그 주차의 정답 상자가 곧 통과 기준이다.

2.2단계 B — 실제 녹음에 적용하기 · stage B · real recordings

결과 절에는 B의 결과만이 아니라 A의 검증 결과(정답과의 차이)를 함께 적는다. 그래야 읽는 사람이 B의 숫자를 얼마나 믿어도 되는지 판단할 수 있다. A에서는 맞았는데 B에서 문제가 생겼다면 그 내용도 결과의 일부로 보고한다. 15주차 발표에서도 A 검증 결과를 한 장 보여 준다.

합성으로 하면 오히려 더 잘 보이는 것

3단계 과제인 지표별 민감도는 합성 자료에서 가장 정확하게 잴 수 있다. 실제 사례에서는 무엇이 원인인지 알 수 없지만, 합성에서는 내가 무엇을 망가뜨렸는지 알고 있기 때문이다.

예를 들어 모음 공간만 줄이고 음원은 건드리지 않았을 때 jitter가 변하는지 확인할 수 있다. 변한다면 그 지표는 특이도가 낮은 것이다. 실제 임상 자료로는 하기 어려운 실험이다. 보고서에는 합성 자료임을 밝히고, 실제 병리와 다른 점을 제한점에 적는다.

z점수를 낼 때 — 규준이 작으면 정상인이 이상해 보인다 · z-scores against small norms

2단계에서는 규준 대비 편차를 z점수(z-score)로 낸다. 계산 자체는 간단하다.

Python 규준 대비 z점수
import numpy as np
import pandas as pd

def z_against_norm(value, norm_values):
    """norm_values: 규준 집단의 측정값 배열 (반 데이터)"""
    ref = np.asarray(norm_values, dtype=float)
    return (value - ref.mean()) / ref.std(ddof=1)

norm = pd.read_csv("class_norms.csv")        # 6~7주차에 모은 반 데이터
case = pd.read_csv("case_measures.csv")      # 사례 화자

for col in ["cpps_dB", "jitter_local_pct", "vsa_Hz2", "artic_rate"]:
    ref = norm.loc[norm.gender == case.gender[0], col]
    z = z_against_norm(case[col][0], ref)
    print(f"{col:<20} z = {z:+.2f}   (규준 n = {len(ref)})")

문제는 규준 표본이 작다는 데 있다. 반을 성별로 나누면 집단당 8~16명쯤 되는데, 그 정도 표본으로 낸 평균과 표준편차는 그 자체가 흔들리는 추정치다. 그래서 완전히 정상인 사람을 규준과 같은 분포에서 뽑아 z점수를 매기는 일을 2만 번 되풀이해 보았다. 이론대로라면 |z| > 2로 나오는 비율은 5 %여야 한다.

표본이 20명 남짓인 수업 프로젝트에서는 p값에 매달리지 않는다. §1.4의 표가 그 이유다. 집단당 20명이면 d = 0.91은 되어야 80 % 확률로 잡히고, 그보다 작은 차이는 실재하더라도 p > .05로 나올 가능성이 더 크다. 그런 상황에서 큰 p값은 “차이가 없다”가 아니라 “이 표본으로는 알 수 없다”는 뜻이다.

  1. A1참 효과크기를 아는 자료로 통계 코드 검증 · 15분

    먼저 손으로 계산할 수 있는 작은 예로 코드를 확인하고, 그다음 research_groups.csv에 돌린다. 이 파일의 두 세트는 참 효과크기를 정해 두고 집단당 16명씩 뽑아 만들었다.

    Python 두 집단 비교 — t-검정과 Cohen's d
    import numpy as np
import pandas as pd
from scipy import stats

df = pd.read_csv("research_groups.csv")
for study, sub in df.groupby("study"):
    a = sub.loc[sub.group == "A", "value"]
    b = sub.loc[sub.group == "B", "value"]
    t, p = stats.ttest_ind(b, a)                       # 등분산 가정 t-검정
    sp = np.sqrt(((len(a)-1)*a.var(ddof=1) + (len(b)-1)*b.var(ddof=1)) / (len(a)+len(b)-2))
    d = (b.mean() - a.mean()) / sp                     # Cohen's d (합동 표준편차)
    print(f"{study}: d = {d:.2f}, t({len(a)+len(b)-2}) = {t:.2f}, p = {p:.3f}")

    두 세트는 평균 50, 표준편차 10인 분포에서 B 집단만 참 효과크기만큼 옮겨 뽑았다. 난수 시드는 결과를 보기 전에 정해 두었고 바꾸지 않았다. 그런데 참 효과크기가 1.0인 세트에서도 이번 표본의 d는 0.56에 그쳤고 p = .123으로 유의하지 않았다. 참 효과크기 0.5인 세트는 차이가 거의 0으로 나왔다. §1.4의 표에 따르면 집단당 16명이고 d = 1.0이면 다섯 번에 한 번꼴로 이렇게 놓친다. 코드는 맞았지만 표본이 작아 결론이 흔들린 것이다. 실제 자료에서 “유의하지 않았다”를 “차이가 없다”로 쓰면 안 되는 이유를 정답을 아는 자료로 확인한 셈이다.

    서울 코퍼스를 쓸 때

    자발화의 토큰은 짧고 축약이 많아서, 합성음에서는 잘 맞던 절차가 값을 내지 못하는 경우가 생긴다. 지속시간이 너무 짧은 토큰을 따로 표시해 두고, 포함한 결과와 뺀 결과를 비교한다. 이용 조건에 따라 출처(Yun et al., 2015)를 밝힌다.

자주 나오는 질문

합성 자료로 검증하는 것이 실제 프로젝트에 도움이 되나요?

코드와 설정이 맞는지 확인하는 데는 합성 자료가 가장 좋다. 정답을 알기 때문에 틀렸을 때 곧바로 알 수 있고, 무엇을 망가뜨렸는지 알고 있으니 지표의 민감도와 특이도도 잴 수 있다. 다만 합성 자료는 실제 병리나 자발화보다 훨씬 단순하므로, A를 통과했다고 B의 결과가 맞다는 보장은 없다. 그래서 두 단계를 모두 하고 둘 사이의 차이를 보고한다.

실제 녹음에는 정답이 없는데 결과가 맞는지 어떻게 판단하나요?

정답 대신 쓸 수 있는 기준을 찾는다. 임상가의 청지각 평정, 연구진이 공개한 측정값, 짝이 같은 기준으로 잰 값, 같은 DB 안의 정상 화자가 그런 기준이다. 어느 것도 참값은 아니므로, 무엇과 비교했는지와 일치 정도를 함께 적는다.

공개 DB에 있는 자료면 마음대로 써도 되나요?

그렇지 않다. 비영리 이용, 출처 표시, 감사 문구, 계정 신청처럼 자료마다 조건이 다르다. 장애음성은 특히 민감한 자료이므로 화자를 추측하거나 파일을 다시 배포하지 않고, 제출물에는 파일 ID와 출처만 적는다.

PVQD의 평정과 제 CPPS가 잘 맞지 않으면 제 측정이 틀린 건가요?

꼭 그렇지는 않다. 평정도 사람의 판단이어서 흔들리고, CPPS가 담지 못하는 음질 특성도 있다. 먼저 A1에서 같은 코드가 입력 순서를 맞혔는지 확인하고, 크게 어긋나는 파일을 직접 들어 본 뒤, 측정 문제인지 평정 문제인지 지표의 한계인지 나누어 적는다.

결과가 유의하지 않으면 프로젝트가 실패한 건가요?

아니다. 연구 트랙 A1에서 보았듯이 참 효과크기가 1.0이어도 집단당 16명이면 놓치는 경우가 있다. 효과크기를 보고하고, 이 표본으로 잡을 수 있는 효과의 크기를 §1.4의 표로 밝히면 정확한 보고가 된다.
